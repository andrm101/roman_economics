## 4. Issues

1. **Spec deviation (moderate): circular records are not "excluded automatically".** Spec section 4 says "Circularly dated records are excluded from that test automatically." `monte_carlo()` excludes only the IDs the caller passes in `exclude`. Without that argument, a planted A<->B pair is kept in the draws (I checked: the draw keys were `['A', 'B']`). The report's wording "drops excluded (circular) records" is accurate only if the caller first runs `circular_records`. An analysis that forgets that step will silently include circular records. Possible remedies, for the researcher to choose: a join-aware MC entry point that calls `circular_records` itself, or a required `exclude` argument. The auditor does not fix this.
2. **Spec-level inconsistency in D033 (for the researcher, not the producer): lag 0 is also an overlap.** Bounds are inclusive, so `B.t_low − A.t_high = 0` means the two intervals share one year. Such a pair is returned by both `overlap_join` and `lag_join` (checked on A=[1,10], B=[10,15]). The spec says "A pair where B starts before A ends belongs to the overlap join, not the lag join". The code follows the formula exactly, but the two joins are not disjoint at lag 0. The researcher should decide whether the lag join should be `1 <= ... <= k`, or whether the overlap is acceptable.
3. **Minor: duplicate `record_id`s collapse silently** in `draw_dates`/`monte_carlo`, because the dict key is overwritten: two intervals with ID "A" produce one draw. Nothing checks for uniqueness.
4. **Minor: `n_draws=True` is accepted** as 1 because of the bool/int subclass. `lag_join` guards against this case for `k`, but `monte_carlo` does not.
5. **Noted, accepted as flagged by the producer:** the downstream-cycle extension, dangling links ending a chain, `dating_method` as a free string (I confirmed no `DatingMethod` vocabulary in code or the graph), `DEFAULT_SEED` not in `config/parameters.yaml`, and the added `record_origin` field. Each needs researcher confirmation. None conflicts with D033.
