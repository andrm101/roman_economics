# T-WP10-001 report (ag-mod)

## Summary

This run implements the shared time model specified in `docs/expansion/02_ontology_and_data.md` section 4, as amended by D033. It replaces the earlier escalation report, whose items 1-6 D033 resolves. [sourced: decision_log D033, spec section 4]

`src/romeco/time.py` provides:
- Conversion between historical and astronomical years (`to_astronomical`, `from_astronomical`). Year 0 is rejected as an input.
- An `Interval` type with the section 4 fields: `t_low`, `t_high`, `t_resolution` (validated against the section 4 list), `dating_method`, `calendar_source`, `dating_dependency`. Bounds are inclusive, so `length = a_high - a_low + 1`.
- Overlap join: `|A∩B| > 0`, with `overlap_frac = |A∩B|/|A|` and `jaccard`, both as exact `Fraction`s.
- Containment join: inclusive, so equal intervals count.
- Lag join: `0 <= B.low - A.high <= k`, with `k` a non-negative int.
- Circular-dating check over `dating_dependency` chains of any length (`is_circular`, `circular_records`).
- A seeded Monte Carlo (`monte_carlo`) that draws uniform integer years. It uses stdlib `random.Random(seed)` with default seed 42, applies a caller statistic to each draw, and drops excluded (circular) records. Its result carries `record_origin = "simulated"`.

Implementation choices not fixed by the spec, flagged for researcher confirmation:
- **Optional `record_origin` field on `Interval`** (default `None`). Not in the section 4 table. I added it so synthetic test fixtures and simulated draws can carry their origin as the AG-MOD rules require. [assumption]
- **Cycle downstream of the start record.** A chain that enters a cycle not containing the start record (A -> C -> D -> C) is also treated as circular. The spec text names only "reaches the other side or returns to itself". My reasoning is that A's date then rests on a circularly dated claim, and excluding it is the conservative choice. [assumption] This is about the circularity rule, not a join rule, so I did not escalate.
- **Dangling dependency links end the chain** and are not circular. [assumption]
- **`dating_method` is a free string, not validated.** No `DatingMethod` vocabulary exists in code or ontology yet (I searched for `DatingMethod` / `dating_method` and found none outside the spec). [sourced: repo search]
- **Seed 42 is a module constant (`DEFAULT_SEED`), not in `config/parameters.yaml`.** D033 fixes the value. Proposal: if the researcher wants it in parameters, add an entry such as `time.mc_default_seed`. [assumption]

No experiment manifest was written, because this is library code and no model run took place. No existing dated record was changed (the contract's forbidden item).

## Not checked

- I did not compare MC reproducibility across Python versions or platforms. It relies on `random.Random` with an int seed, which is stable across CPython 3.x. I tested it only on Python 3.14.3.
- I did not run a formal statistical test of uniformity. The count check is a coarse sanity bound, not a chi-square test.
- I did not measure join performance. The joins are O(|left|·|right|) nested loops, which is fine for small registers but may need an interval index for large datasets.
- I did not wire the module into existing records, `evidence_db` or the ontology. I also did not check whether existing modules use a different BCE or year-0 convention.
- No `calendar_source` conversion rules are implemented. The spec calls them "a named rule, like units", but the contract does not ask for them.
- I did not append a `registers/research_log.md` entry, because that file is outside the ag-mod write grant.
