## Summary

This task changes library code only, so no experiment was run and no `experiments/<E-id>/manifest.yaml` was needed. No parameters were read or changed. Every interval in the tests is a planted fixture with `record_origin = "synthetic"`, and `MonteCarloResult` is still marked `record_origin = "simulated"`.

Changes to `src/romeco/time.py`:

1. **D034 lag join.** `lag_join` now keeps a pair only when `1 <= B.low - A.high <= k`, so lag 0 (a shared year) is an overlap-join pair only. I did not change `k` validation: it must be an int >= 0, and `k = 0` is accepted and returns no pairs. Overlap and containment semantics are unchanged. [sourced: D034; spec §4]
2. **Automatic circular exclusion (audit issue 1).** [sourced: spec §4 "excluded from that test automatically"]
   - `monte_carlo(intervals, ...)` now finds circular records and drops them, even when the caller passes no `exclude`. A flat list has no join sides, so only the spec's "returns to itself" criterion applies. That covers a cycle of any length, plus a chain that runs into a cycle further on, which keeps the T-WP10-001 behaviour. Links come from the intervals' `dating_dependency` and the new optional `extra_dependencies`. [assumption: if no join is given, the "other side" criterion does not apply]
   - New `monte_carlo_join(left, right, ...)` applies the full spec rule (reaches the other side, or returns to itself) by calling the existing `circular_records`. It then draws over `left` followed by `right`.
   - The caller's `exclude` is merged with the detected set. `MonteCarloResult` gains a `circular` field (default empty, so existing code still works). `excluded` is still the full set of records dropped.
3. **Duplicate IDs (audit issue 3).** New `check_unique_ids`. `draw_dates`, `monte_carlo` and `monte_carlo_join` raise `ValueError` on a duplicate `record_id`. For `monte_carlo_join`, the check covers both sides together.
4. **n_draws (audit issue 4).** `bool` is now rejected along with non-int and < 1 values. This raises `ValueError`, the same type as before.

Why this did not trigger the escalation condition: the spec defines "the other side of the join" whenever a join exists. `monte_carlo_join` takes the two sides explicitly, and the flat `monte_carlo` applies only the criterion that needs no sides. Neither entry point needs join context that the spec leaves undefined. The researcher should confirm the flat-list reading (see Not checked). [assumption]

Changes to `tests/test_time.py`:

- In T-WP10-001's `test_lag_join_boundaries`, lag 0 is no longer expected to match, and a lag-1 case was added. This is the only T-WP10-001 test I changed, as the contract allows.
- Ten new test functions, which collect as 16 tests because one is parametrised over 7 values.
